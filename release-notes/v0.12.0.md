# Bigger on the inside

The X4 and X3 profiles move to CrossPoint 2.0, and the firmware understands a lot more of your book now. So we keep a lot more of it.

## New & Noteworthy

**Built for CrossPoint 2.0.** The new firmware reads far more CSS than 1.6 did. Until now we stripped all of it, because the device ignored it anyway. Not any more. A fitted book keeps:

- font sizes (headings and small print look like the publisher meant them)
- small caps
- borders around boxes
- drop caps
- page breaks before chapters and parts
- lists without bullets, when the book asks for that
- styles with ids, nested selectors and several classes

Each chapter's own styles still apply to that chapter only. Nothing leaks into the rest of the book.

Your font size stays yours, though. A book that sets its body text to 0.9em or plays games with the root size would drop all text a full step on the device. So we keep sizes that mean something (headings, small print, drop caps) and leave body text to the size you picked on the reader.

**Shaded boxes show up.** CrossPoint 2.0 can shade a box with a light background, like a tip, a warning or a summary. Our gray remap turned every background white, so you never saw one. A light background now becomes a gray the device shades. A dark background (a "night mode" book) still turns white, so the text stays readable. So does a paper tint on the whole page: nobody wants every page dithered.

**Wider tables stay tables.** CrossPoint 2.0 lays out a table as a grid with up to 160 words per row. The old limit was 32 words per cell. More tables now keep their grid instead of being turned into labeled paragraphs. A table with a line break or a list item in a cell is the exception: the device gives up on the grid for those, so we write them as paragraphs ourselves (they read better that way).

**Numbered lists hang.** CrossPoint 2.0 indents the first line of every paragraph by default. That pushed the numbers of our numbered lists to the right, and the first line of a code block or a table cell too. List numbers now hang in the margin and the wrapped lines line up after them. Code blocks and table cells start at the margin again.

**Other CrossPoint readers.** CrossPoint runs on more than Xteink by now. The README says which profile fits which reader. `x4` suits every 480x800 one: the X4, X4 Pro and X4C, the Seeed Sticky, the M5PaperMono, the BOOX Picco and the Metalio E-Ink 4. `x3` is for the X3. The EEGOREAD A4 works with `x4` too (images come out a little smaller than its screen).

## Fixes

- **Diagrams drawn right in the chapter text lost their styling on the X4 and X3.** An inline SVG's own `style` attributes went through the device CSS filter before we turned the diagram into a picture, so fills and text sizes were gone. They stay now, and the picture looks like the diagram.
- **The app could miss the end of a fit.** With a fast book the "done" signal sometimes arrived before the CLI's last lines. Fixed with the newer shell plugin.
- **The app could freeze while it saved its settings.** Fixed with the newer store plugin.
- **A failed update could delete the app on macOS.** The update now swaps the app in one step or keeps the old one.
- **Security updates for the online metadata lookup.** The TLS library got several fixes, among them one where certificate checks could accept intermediates that are no longer trusted.

## Breaking changes

None. Three behaviour changes worth naming:

- The X4 and X3 profiles target CrossPoint 2.0 now. On firmware 1.6 the extra CSS does nothing and some wide tables lose their grid. Update your reader (it's a free update over the air).
- Fitting a book again gives a different result than before, because more CSS survives. Use `--force` to refit books that were already fitted.
- A chapter that is nothing but one shaded box comes out white. To us it looks exactly like a tinted page.
